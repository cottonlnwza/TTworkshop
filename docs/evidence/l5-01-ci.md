## What the one work PR implements

- `.github/workflows/ci.yml`: PR and push checks on `sprint_2_staging`/`main`; `npm ci` lockfile install, `npm run build`, disposable PostgreSQL 15 service, actual Chromium installation, 13-file real PostgreSQL/Chrome test suite; output artifact also retained on failure. Job `build-test` uses permissions `contents: read` and a synthetic test-only database account.
- Test URLs are *strictly local* and name only `ttworkshop_test` and `ttworkshop_seed_test`. The seed suite may create the second isolated database; the CI database account owns the first database and can create the second. Never target the development or GCP database. PostgreSQL is a container service scoped to the CI job.
- The initial [red CI run #43404247904](https://github.com/cottonlnwza/TTworkshop/actions/runs/43404247904) on `18237c87f22fbb2a73fd887ab6685231b5f86ac5` intentionally used **`ttworkshop_negative_demo`** in `PG_TEST_URL`. Dependency install, build and Chromium installation had passed. On the *same* PR the corrected workflow now uses **`ttworkshop_test`**.
