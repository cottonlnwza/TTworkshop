## 1. Requester-authorized Working Decisions

The Issue requester authorized these defaults for specification-first work. They are not global product decisions. Reviewer Round 3 recorded implementation-only authorization on exact specification HEAD `6c6b0275585c6bc3f44dfbcc37b9bb6c99318316`; the Author verified the Reviewer was distinct from the Author and verified the exact SHA before dependent TDD/implementation. This gate is not Formal APPROVE or merge permission.

1. **WD-F04-01 — Privacy:** Participant reads only their own registration and minimum Workshop summary (`workshop_id`, `title`, `starts_at`). Organizer roster exposes only `registration_id`, opaque `participant_id`, `status`, `registered_at`; no Participant email or full name.
2. **WD-F04-02 — Pagination / ordering:** default 20, maximum 50; cursor pagination; stable `registered_at DESC, id DESC`; opaque `next_cursor`; no total count.
3. **WD-F04-03 — API / DTO:** `GET /api/v1/me/registrations`, `GET /api/v1/me/registrations/:id`, `GET /api/v1/organizer/workshops/:id/registrations`; success `data`, list pagination metadata, errors `error`.
4. **WD-F04-04 — HTTP errors:** anonymous `401 UNAUTHENTICATED`, wrong role `403 FORBIDDEN` (reuse existing F-01 middleware semantics), foreign/missing private registration or foreign/missing/unpublished Workshop `404 NOT_FOUND`; generic safe error bodies without private data.

Identity and ownership must be derived/enforced server-side from the authenticated session. Organizer roster access is restricted to an owned **PUBLISHED** Workshop; own DRAFT, foreign and missing Workshop IDs return the same safe unavailable outcome. UI states include loading, empty, error, expired session and forbidden/unavailable. The scope excludes cancellation/re-registration, check-in, attendance, statistics/reporting, Admin privilege, unrelated Workshop changes and schema migration by default.
