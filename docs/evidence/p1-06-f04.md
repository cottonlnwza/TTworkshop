## 1. Requester-authorized Working Decisions

The Issue requester authorized these defaults for specification-first work. They are not global product decisions and remain subject to Independent Reviewer review on the exact Draft PR HEAD.

1. **WD-F04-01 — Privacy:** Participant reads only their own registration and minimum Workshop summary (`workshop_id`, `title`, `starts_at`). Organizer roster exposes only `registration_id`, opaque `participant_id`, `status`, `registered_at`; no Participant email or full name.
2. **WD-F04-02 — Pagination / ordering:** default 20, maximum 50; cursor pagination; `registered_at DESC, id DESC`; opaque `next_cursor`; no total count.
3. **WD-F04-03 — API / DTO:** `GET /api/v1/me/registrations`, `GET /api/v1/me/registrations/:id`, `GET /api/v1/organizer/workshops/:id/registrations`; success `data`, list pagination metadata, errors `error`.
4. **WD-F04-04 — HTTP errors:** anonymous `401`, wrong role `403`, foreign/missing private registration or foreign/missing workshop `404`; generic safe error bodies without private data.

Identity and ownership must be derived/enforced server-side from the authenticated session. UI states include loading, empty, error, expired session and forbidden/unavailable. The scope excludes cancellation/re-registration, check-in, attendance, statistics/reporting, Admin privilege, unrelated Workshop changes and schema migration by default.
