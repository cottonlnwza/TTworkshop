# DEC-10 / ARCH-01–02/07 — F-01 scoped stack and session implementation

Under Skill v1.3.4, a teammate's APPROVE + MERGE of this feature PR accepts these **scoped** implementation choices; **no additional two-student formal signature is needed**. Do not claim an instructor-approved specification or that unrelated open design choices have been decided.

| Decision | F-01 implemented choice | Reason / tradeoff |
|---|---|---|
| Web | React 19 + TypeScript + Vite 8 | Accessible labels and client state, separate testable UI; role only displayed after `/auth/me`/login server response |
| API | Express 5 + TypeScript running on Node.js | Role middleware at server, versioned `/api/v1` endpoints, structured JSON errors; no trusted role or owner read from client |
| Durable DB | PostgreSQL 15+ with `pg` SQL driver, versioned `db/migrations/001_auth.sql` | Real relational users/sessions/FKs, indexed session lookup; leaves Postgres row locks and partial unique indexes available to F-03. No ORM selected for F-01. No fake DB for integration |
| Identity | Seeded Participant/Organizer; normalized lower-case+trim unique email; scrypt with a **fresh independent random 16-byte salt for each seeded account** and 64-byte derived key | Only synthetic accounts; no self-register/reset/admin scope. Passwords are hashed and not returned by API; independent salts are tested |
| Session | Opaque, uniformly random **32-byte token** in `ttw_session` HttpOnly cookie; DB stores **SHA-256 digest** only; expiry 8 hours; per-session logout revokes row | Signed-in identity resolved on each request against valid nonrevoked session; theft/replay/expiry limitations noted. No token in JSON. New login creates a new independently revocable session |
| Cookie/CSRF | `SameSite=Strict`, `Path=/api/v1`, `HttpOnly`, `Secure` when production; reject Origin not equal to configured `APP_ORIGIN` on all mutating auth and role-reserved POST requests | Explicit single-origin UI via dev proxy; prevents cross-site form POST/CSRF. Production `APP_ORIGIN` must be HTTPS. Dev insecure HTTP is **localhost only**, never deployed over plain HTTP |
| Privacy | `Cache-Control: no-store` on `/api/v1/auth/*`, generic invalid-credential messages, constant-work scrypt for unknown email, JSON without token or password hashes | Avoid private-data caches, avoid account enumeration and accidental credential leakage |
| Test policy | Vitest + supertest + **real PostgreSQL**; Testing Library/jsdom; Playwright Core with local headless Chrome | Reproducible API/DB/role negative tests and actual browser login/logout/reload; explicit RED→GREEN and build evidence |

**PR #9 Reviewer correction R-01–R-04:** Each account is seeded with an independently generated salt; destructive test setup verifies an **exact loopback PostgreSQL URL pathname and actual server database/IP** before migrations or truncation; no-store runs before JSON parsing and applies to malformed auth payloads; browser `/auth/me` distinguishes `401` from `403` and server/transport failures with retry.
